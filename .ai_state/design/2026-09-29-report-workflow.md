# 日报流程与发布保障

## 方案

- Refactor；复用当前干净工作区。按「草稿操作 → CI/交互回归 → 导航/动效/小屏」三个切片交付。
- 单日、一周批量、历史重新发布共用项目草稿操作。页面只负责选择范围、确认、队列、刷新和通知；删除无调用方的旧生成/保存入口与预览组件。
- 沿用现有 Node 业务测试，补真实页面点击回归；PR 和发布复用同一验证工作流。
- 保留四项日报功能，改为任务名称与输入/输出说明。欢迎页显示真实配置状态；去除工作区鼠标倾斜反光；奖励播放按需加载。
- 先以 1366×768、125%/150% 等效可用空间运行布局回归，再根据系统 workArea 设置窗口边界。

## 验收标准

- [x] 生成失败/取消保留正文和已成功发布状态；项目人工素材不串项目。
- [x] 编辑后发布先保存最新正文；保存失败不远端提交。
- [x] 部分发布成功后的批量重试不重提成功项；本地刷新失败不改变远端成功状态。
- [x] PR 与发布均运行现有业务测试、类型检查、构建与关键交互测试。
- [x] 四个入口名称及说明一致；欢迎页显示仓库、汇报人、AI 配置状态。
- [x] 编辑卡片无鼠标倾斜；奖励组件未触发时不加载。
- [x] 小屏与缩放下编辑区、主按钮和发布结果可滚动访问。

## 实际调用证据

- reportState.generate/generateAndPush 仅孤立 ReportPreviewCard 引用，saveCurrentReport 无调用方。
- HistoryLogsView.republishActiveReport 仍使用 push；必须迁移后删除。
- weeklyReportActions 有第三套 CRUD；统一到 projectReportActions。
- 单日 publishableDrafts 未排除成功项，周批量已排除。共享重试规则补齐此差异。
