# 仓库关联飞书项目

## 方案

在现有 AppConfig 增加按规范化仓库路径保存的飞书项目关联，复用现有项目选项接口和配置保存通道，不新增依赖、数据库表或 IPC。关联记录保存选项 ID、名称及当前表单 shareToken/projectFieldId，避免切换表单后误用旧关联。旧配置默认空映射。

仓库中心添加目录后，展示本次识别的仓库并允许逐个关联项目；可跳过关联。已有仓库也可修改/清除关联，名称和关联集中在同一编辑入口。明确区分“仓库已添加”和“关联保存成功”，失败保留编辑内容且不显示保存成功。刷新保留关联，移除仓库清理对应关联。

单仓库日报、按仓库批量日报、一周补日报和历史草稿恢复共用关联解析。明确传入的草稿选择优先；仓库关联优先于全局默认；无关联保持全局默认。合篇来源全部解析到同一项目时自动带入，否则留空让用户确认。保留用户已编辑的草稿项目，不在发布时静默改目标。项目名称在元数据暂未加载时仍可从匹配的关联显示。

仓库列表使用统一主色表达选中状态，置顶以小标识表达；显示名称、路径、飞书关联和操作分区清晰，保留搜索、选中、置顶、移除。支持按项目名搜索及深浅主题；局部样式改现有 _report.scss，不覆盖工作区在途全局主题/工作台改动。

## 验收标准

- AC1：旧配置正常加载；关联可保存/重载，刷新不丢失，移除清理；保存失败不产生虚假成功。
- AC2：添加仓库后逐个关联，已有仓库修改/清除关联；项目可搜索、刷新；未连接飞书可跳过并显示配置入口。
- AC3：新日报、批量、一周及历史恢复按仓库预选项目并传入正确发布 ID/名称；手动选择保留。
- AC4：合篇同项目自动预选，混合项目不擅自选择；切换飞书表单不会使用旧关联。
- AC5：仓库中心视觉层级清晰，无选中/置顶双色大面积冲突；1366px 下无横向溢出；保留既有仓库操作。

## Done Contract

- 配置/仓库状态/日报关联的行为回归通过，覆盖 AC1、AC3、AC4。
- npm run check 通过，既有相关工作流回归通过。

## Round 1 · Critic Findings

- P1：备份恢复校验遍历 DEFAULT_CONFIG 必填字段，新增映射会拒绝旧 v1 备份。修复：旧备份缺本次新增映射时补空映射后按原规则校验，并加旧备份恢复回归。
- 仓库添加当前吞保存异常且返回 void；实现需明确成功结果，关联保存失败只回滚本次设置，弹窗输入保留。
- P1：切换表单时缓存项目与现有草稿仍指向旧表单。只监听表单身份（shareToken/projectFieldId）变化，清除旧选项和日报/一周草稿目标，保留正文工时。首次加载正常解析已保存关联。
- 备份原有策略会清空 shareToken；关联内同名信息也遵守脱敏策略，恢复后不得误用脱敏后的关联。
- 结论：按上述约束实现，不增加通用兼容层。
