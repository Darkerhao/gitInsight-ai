# 打通甲子农场 ↔ 甲币经济

> 2026-07-07 · 让签到得来的甲币真正「花得出去、赚得回来」

## 背景

改动前，甲币系统是一套「坏掉的经济」：

- 每日签到随机发放 **8,888–88,888** 甲币，量级极大；
- 唯一消费口是顶栏的轻量特效商店，单价仅 **4–14** 甲币；
- 结果甲币永远花不完，只是个不断变大的数字。

同时，**甲子农场与甲币是两套完全独立的系统**：农场用 露水 / 阳光 / 养分 / 成长值运转，与甲币零关联。

本次改动把两者打通，为甲币建立**大额消费口**与**产出回路**，让签到、农场两个功能互相咬合。经济量级保持「巨大数字」，新消费口也做成大额。

## 新增的四类玩法

| 玩法 | 说明 | 花费 / 产出 |
|---|---|---|
| **浇灌** | 花甲币购买 露水 / 阳光 / 养分，浇灌同时增加成长值 | 每次 8,888 甲币 → +25 资源 +20 成长 |
| **一键催熟** | 花甲币直接把成长值补满到收获线 | (收获线 − 当前成长) × 888 甲币 |
| **收获反哺** | 收获作物时按作物档次 × 地块等级折算，反发甲币 | 见下方作物表 × 地块等级 |
| **解锁高阶作物 / 新地块** | 甲币解锁更高档作物与更多地块 | 见下方解锁定价 |

### 作物等级树（farm-wide 线性解锁）

| 档次 | 名称 | 收获所需成长 | 收获反哺甲币（基准/级） | 解锁花费 |
|---|---|---|---|---|
| 1 | 日报稻 | 100 | 6,666 | 0（默认拥有） |
| 2 | 代码麦 | 160 | 18,888 | 60,000 |
| 3 | 协作花 | 240 | 48,888 | 280,000 |
| 4 | 灵感树 | 360 | 108,888 | 888,000 |

> 收获反哺 = `该作物基准 × 收获时地块等级`。地块每收获一次等级 +1，反哺随之增长。

### 地块解锁定价（最多 4 块）

| 地块 | 解锁花费 |
|---|---|
| 1 号 | 0（默认拥有） |
| 2 号 | 88,888 |
| 3 号 | 288,888 |
| 4 号 | 888,888 |

> 以上数值均为 [electron/main/jiaziFarm.ts](../electron/main/jiaziFarm.ts) 顶部常量（`CROP_TIERS` / `PLOT_UNLOCK_COSTS` / `WATER_PACK` / `COIN_PER_GROWTH`），可随时调整。

## 数据模型改动

改动前 `jiazi_farm_state` 是单行（`id CHECK(id=1)`），直接持有资源与成长。改为「农场元信息 + 多地块」：

- **`jiazi_farm_state`**（保留，id=1，作为 farm-wide 元信息）新增两列：
  - `unlocked_crop_tier`（已解锁最高作物档次，默认 1）
  - `unlocked_plot_count`（已解锁地块数，默认 1）
  - 原 water/sunlight/nutrient/growth/level/total_harvests 列变为 legacy，迁移后不再读取（留列不删）。
- **`jiazi_farm_plots`**（新表）：每块地一行，持有 crop_tier / 资源 / 成长 / 等级 / 收获次数。

**一次性迁移** `ensureJiaziFarmPlots`（[electron/main/database.ts](../electron/main/database.ts)）：照现有 `ensureDailyReportTimeRangeColumns` 的 PRAGMA + ALTER 模式，建表 + 补列后，若 `jiazi_farm_plots` 为空且旧 state 行存在，则把旧 state 的资源/成长/等级搬进 1 号地块 —— **保住老用户已有进度**。

## 主进程改动

- **[electron/main/checkinWallet.ts](../electron/main/checkinWallet.ts)**
  - 新增 `awardCheckinCoins(...)`：加币 + 记 `type:'reward'` 交易，供收获反哺复用。
  - 新增 `broadcastWallet(...)`：通过 `sendToMainWindow('checkin-wallet:updated', ...)` 广播钱包快照；`runDailyCheckin` / `spendCheckinCoins` / `importCheckinWallet` / `awardCheckinCoins` 成功后均调用。
  - 农场所有花费复用现成的 `spendCheckinCoins`（自带余额校验、抛「甲币不足」、记账）。
- **[electron/main/jiaziFarm.ts](../electron/main/jiaziFarm.ts)**（改动最大）
  - 顶部新增数值常量；重构 `getJiaziFarmSnapshot` 返回 farm 元信息 + `plots[]` + `cropTiers[]` + `plotUnlock` + `coins` + 定价信息。

## IPC 四层同步

按项目约定，跨进程改动四处同步（否则类型与运行时静默漂移）：

1. **[electron/main/ipc.ts](../electron/main/ipc.ts)** — 注册 5 个新 channel：`jiazi-farm:water`、`jiazi-farm:quick-ripen`、`jiazi-farm:plant`、`jiazi-farm:unlock-crop-tier`、`jiazi-farm:unlock-plot`。
2. **[electron/preload.ts](../electron/preload.ts)** — 新增对应 `invoke` 包装 + `onCheckinWalletUpdated` 订阅（返回反订阅函数）。
3. **[src/renderer/src/env.d.ts](../src/renderer/src/env.d.ts)** — 补齐 `window.api` 方法签名与订阅。
4. **[src/shared/types.ts](../src/shared/types.ts)** — 重构 `JiaziFarmState` / `JiaziFarmSnapshot`，新增 `JiaziFarmPlot` / `JiaziFarmCropTier` / `JiaziFarmPlotUnlock` 及三个 payload 类型；交易 type union 加 `'reward'`。

项目无测试框架。已完成的静态验证：

- ✅ `npm run typecheck` 通过（四层类型对齐无 drift）
- ✅ `npm run build` 三个 bundle 目标编译通过

- 浇灌 / 催熟：扣币正确、资源与成长增加、顶栏余额实时刷新；

- 余额不足：各操作报中文「甲币不足」且不崩溃。
