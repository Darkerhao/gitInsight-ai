# 码迹AI 产品体验与界面优化计划

- 日期：2026-11-19
- 适用分支：`dev`
- 文档状态：产品体验优化已实施。
- 原则：以最少代码解决明确的使用问题，沿用现有 Electron、Vue、Element Plus、IPC 和配置状态。

## 1. 目标

本计划指导后续产品体验和界面优化，依次解决配置入口重复、工作台操作重复、页面语义和视觉规则不统一的问题。日报生成、自动同步和本地数据的业务规则不在本轮重新设计。

## 2. 审查基线

- `npm run check`：类型检查和生产构建通过。
- `npm test`：启用的测试通过；发布测试中按配置跳过的场景保持原状。
- `node tests/ui-shell.smoke.mjs`：失败。脚本将普通 `✓` 状态符号误识别为 emoji，不是产品运行时故障。
- 使用 mock IPC 的 renderer 在 1366px 和 900px、浅色和深色主题下完成截图检查；未发现横向溢出或明显控件重叠。
- 构建仍会提示 ECharts、3D 相关 chunk 大于 500 KB。奖励特效已经按需加载，ECharts 也已从完整包收敛到 Core；本计划不重复实施旧审计中已完成的体积优化，只有运行数据证明进入耗时仍影响用户时才重新评估。
- 审查时本地 `dev` 比 `origin/dev` 落后一提交；实施前已 `git fetch origin dev`，确认仅更新版本元数据后快进到 `d4e1905`（v3.11.1）。

## 3. 开发约束

- 一个配置域只保留一个主要编辑入口；其它页面展示摘要并提供跳转。
- 不新增状态管理库，不复制配置持久化、校验或 IPC 逻辑。
- 先完成一个工作包，再验证并更新本文件状态；不要把所有视觉和导航问题放进同一个大改造。
- 保留 `码币工坊`、`时间长河`、奖励特效剧场的独立视觉，不让工作台主题调整覆盖这些专用场景。
- 不修改后端、数据库 schema、Git 采集规则、日报事实边界、飞书发布幂等逻辑。
- 用户可见文案使用中文；所有保存、复制和发布失败都要保留用户内容并提供明确反馈。
- 跨 IPC 修改须同步维护 `electron/main/ipc.ts`、`electron/preload.ts`、`src/shared/api.ts` 和共享类型。

## 5. 工作包

### P1-01 配置入口与保存边界

**实施结果（2026-11-19）**

- “日报配置”只保留 Git、汇报人与飞书字段；“AI 设置”继续使用同一配置面板维护 AI 档案；自动同步表单只留在“同步任务”。
- 系统设置的集成区改为只读摘要，并可跳转到三个对应编辑页。
- 移除系统设置和同步任务页重复的保存按钮，统一由顶栏“保存全部配置”处理；保存状态改为“配置已保存/有未保存修改”。
- 移除旧 AI 折叠表单和无效面板状态。AI 档案、候选项的新增和删除先更新编辑状态。可通过顶栏主动保存，生成日报、解析飞书字段等操作沿用原有的保存流程。校验异常会显示错误并保留修改。
- 生成页、素材页和使用帮助中的旧配置提示与跳转同步调整为实际入口，避免继续把 AI 或定时任务引导到日报配置。
- 验证：可靠性专项 100/100、自动同步 7/7、类型与构建通过；配置摘要值与三处跳转、保存失败后重试、AI 编辑保存边界、运行态合并与保存并发均有通过的回归。

**现状**

自动同步任务同时出现在“日报配置”和“同步任务”；系统设置又提供工作目录、AI 地址、模型和默认工时的第二套编辑控件。AI 配置在“日报配置”和“AI 设置”也有重复编辑入口。虽然共享同一配置对象，用户仍难判断应该在哪修改、由哪个按钮保存。

**涉及文件**

- `src/renderer/src/views/ReportConfigView.vue`
- `src/renderer/src/views/SyncTasksView.vue`
- `src/renderer/src/views/SystemSettingsView.vue`
- `src/renderer/src/components/panels/AdvancedConfigPanels.vue`
- `src/renderer/src/components/AppTopbar.vue`

**实施方案**

1. “同步任务”成为自动同步任务唯一的主要编辑入口，保留任务列表、任务日历和执行操作。
2. “日报配置”保留 Git、汇报人、飞书和表单映射设置；“AI 设置”成为 AI 配置档案及连接测试的唯一编辑入口。
3. “系统设置”的“集成配置”改为只读摘要，并提供到日报配置、AI 设置、同步任务的跳转。
4. 复用现有配置状态与保存流程。若 `AdvancedConfigPanels` 需要分开 AI 和飞书配置，只增加一个明确的显示模式，不复制表单或保存逻辑。
5. 顶栏保存状态显示“配置已保存/有未保存修改”；页面自己的保存按钮只保存该页面负责的业务对象，不让多个按钮含义重叠。

**验收标准**

- 自动同步任务只在“同步任务”页编辑；AI 档案只在“AI 设置”页编辑。
- 系统设置摘要值与对应编辑页一致，跳转可到达正确页面。
- 每个保存按钮的文案准确说明保存范围；失败时保留修改且可重试。
- 配置持久化、自动同步编辑和保存并发测试通过。

- 消息/历史筛选器和 AI 地址/模型删除、日志详情关闭图标补充了可访问名称，全局焦点可见样式继续保留。
- 验证：类型检查、UI smoke 和浏览器回归通过；全部路由验证一个主内容区与一个页面一级标题。键盘跳过导航会聚焦主内容且保留当前 hash 路由。

**现状**

应用壳层已有 `<main>`，工作台和配置页内部仍嵌套 `<main>`；顶栏问候语和每页标题同时使用 `<h1>`。部分快捷筛选控件和图标删除按钮缺少可访问名称。

**涉及文件**

- `src/renderer/src/components/AppTopbar.vue`
- `src/renderer/src/components/common/PageHeader.vue`
- `src/renderer/src/views/DashboardView.vue`
- `src/renderer/src/views/ReportConfigView.vue`

- `src/renderer/src/views/HistoryLogsView.vue`

**实施方案**

1. 应用壳层保留唯一主内容区；视图内部的 `<main>` 改为 `<section>` 或 `<div>`。
2. 顶栏问候语改为普通文本，每页标题继续由 `PageHeader` 提供。
3. 增加跳过导航链接，键盘用户可直接进入主内容。
4. 给筛选器和图标按钮补充 label 或 `aria-label`，保留全局 `:focus-visible` 焦点样式。

**验收标准**

- UI smoke 覆盖主内容区、标题和图标按钮名称。

**现状**

### P2-01 复制和导出反馈

**实施结果（2026-11-19）**

- 新增 `src/renderer/src/utils/clipboard.ts`，日报、历史日志、素材日报、消息和本地目录共用复制反馈；拒绝权限或 API 不可用时不抛出未捕获异常，保留内容并提示手动选择复制。
- 空内容阻止复制；素材日报补充导出函数自身的空内容检查。既有下载正常，未改动 Object URL 释放时机。
- 验证：复制工具 3/3 单测；四类内容的复制拒绝浏览器回归通过，正文均保留且无未捕获异常；日报、历史和素材 Markdown 下载通过，日报与历史导出额外核对了文件完整正文。

**现状**

日报生成页和历史日志页直接调用 `navigator.clipboard.writeText`，没有捕获权限或系统剪贴板错误；不同页面的失败反馈不一致。

**涉及文件**

- `src/renderer/src/views/ReportGenerateView.vue`
- `src/renderer/src/views/HistoryLogsView.vue`
- `src/renderer/src/views/MaterialReportsView.vue`
- `src/renderer/src/views/MessageCenterView.vue`

**实施方案**

1. 在现有 renderer 工具位置增加一个小型复制函数，统一成功和失败反馈。
2. 复制失败时保留内容并提示用户手动选择；不引入剪贴板依赖。
3. 清理重复的 try/catch 与重复文案。
4. 导出链接按现有浏览器下载流程验证，只有出现真实失败再调整 Object URL 释放时机。

**验收标准**

- 剪贴板 API 拒绝时无未捕获异常，页面显示可理解的失败提示。
- 日报、历史日志、素材日报和消息中心的复制反馈一致。
- 空内容不会触发复制或导出。

### P2-02 视觉规则收敛

**实施结果（2026-11-19）**

- 普通业务页卡片采用实色表面、可见边框和 16px 圆角，移除普通卡片及次要按钮的高光和阴影；主要操作和少量重点展示保留强调。
- 仓库选中/焦点、AI 档案选中、Git 标签和开关焦点改用主题令牌；图表与成功/失败等语义颜色保持原口径。
- 主内容区使用 `data-page` 限定普通页面样式，工坊纪念卡、时间长河和奖励特效继续使用原有材质；移除问候语旧标题样式和已失效的提示卡覆盖。
- 验证：8 个相关业务页 × 2 个窗口（1366×768、900×600）× 2 种主题，共 32 张截图已检查，页面与主内容均无横向溢出。工坊、纪念卡和专注场景的既有浏览器回归也通过。

**现状**

工作台、表单和普通数据区普遍使用带高光边框、阴影和较大圆角的卡片；同时有部分状态仍使用硬编码蓝色，而全局主色为绿色。浅色和深色界面整体可读，但大量区块拥有接近的视觉重量。

**涉及文件**

- `src/renderer/src/styles/_atelier.scss`
- `src/renderer/src/styles/_theme.scss`
- `src/renderer/src/styles/_shell.scss`
- `src/renderer/src/styles/_dashboard.scss`
- 必要时补充局部样式，而不调整 `CoinWorkshopView.vue`、`JiaziTimelineView.vue` 和奖励特效样式

**实施方案**

1. 将工作台、设置、历史、表单卡片改为较平的表面，使用边框、间距和标题层级区分区域。
2. 只在当前主操作、活动选择和少量重点统计上使用阴影、高光或强调底色。
3. 把仓库选择等普通选中/焦点状态改用现有 `--c-primary`、`--c-primary-soft` 等主题令牌。
4. 保留图表的语义色（成功、失败、草稿），不为追求统一而将状态色全部改成主色。
5. 不做全站重写；逐页迁移并删除已被新规则取代的局部重复覆盖。

**验收标准**

- 1366×768 和 900×600 下，页面标题、主操作、辅助区块有清楚且稳定的层级。
- 浅色和深色主题下按钮、选中项、焦点和卡片边界一致，无残留蓝色交互状态。
- 工作台和日报生成页不依赖大面积发光、玻璃高光来表达选中或重要性。
- 专用成长和特效页面保持自身视觉，不被全局样式误覆盖。

**实施结果（2026-11-19）**

**涉及文件**

- `tests/ui-shell.smoke.mjs`
- `src/renderer/src/components/rewards/effects/CodeMaterializeEffect.vue`
- `package.json`

**实施方案**

2. 把 UI smoke 纳入 `npm test`，前提是该检查不再与有效文案冲突。

**验收标准**

- `node tests/ui-shell.smoke.mjs` 通过。
- 增加一条包含普通 `✓` 的正例和一条真实 emoji 的负例。
- `npm test` 能执行 UI smoke 且不会因普通符号误报。
